- (direction) User asked for an Offset tool in sketch mode; sketch mode currently has 14 tools (None..Airfoil) and none of them offsets a curve
- (decision) Classified architectural (lean spec): one novel geometry algorithm plus touchpoints across 7 files and 3 UI layouts
- (decision) Spec folder lives in the repo at docs/specs/spec-sketch-offset/ rather than the configured shared _bmad-output, so the contract is version-controlled with the code and travels with the PR
- (decision) Offset lives in SketchTool.cpp with SketchPlugin.cpp as mode host, NOT a new src/plugins/OffsetPlugin.cpp; this corrects an earlier reading of CONTRIBUTING -- Mirror, Dimension and Airfoil all sit in SketchTool and SketchPlugin is itself the plugin, so the features-live-in-plugins rule is already satisfied
- (decision) Mirror is the end-to-end template: beginOffset/cancelOffset/getOffsetPreview/commitOffset mirroring beginMirror/cancelMirror/getMirrorPreview/commitMirror, which already capture a selection, drag live and write real entities
- (constraint) SketchToolMode::Offset must be APPENDED after Airfoil, never inserted; the header states the toolbar mirrors the enum raw INDEX and hardcodes those indices, so a mid-list insert silently highlights the wrong button
- (decision) Interaction is select-then-drag (user choice): cursor side picks the sign, cursor distance sets magnitude, live ghost preview, exact value via the existing typed-value popup, Escape cancels
- (decision) v1 accepts closed chains only (user choice); splines in the selection are refused with a message rather than degraded to sampled segments
- (event) Throwaway OCCT spike run against 7.9.3 on a closed rounded rect (40x20, r=5) and an open L, to settle three assumptions the design rested on before committing to them
- (note) Spike result 1: BRepOffsetAPI_MakeOffset emits ONLY GeomAbs_Line and GeomAbs_Circle for line/arc input (Other=0 at +3, -3 and -6), so converting the result back to editable sketch entities is total and needs no BSpline fallback
- (constraint) Spike result 2: an offset that collapses the loop returns IsDone()==true with a non-null but EMPTY shape (0 edges at -11 and -40); IsDone() alone is therefore not a sufficient guard and the edge count must also be checked, or the tool silently commits nothing
- (constraint) Spike result 3: open wires do not fail on 7.9.3 but produce a closed racetrack outline around the path (7 edges for both +3 and -3), i.e. SvgImport stroke-to-outline behaviour, not a parallel curve on one side; this is the concrete reason v1 is closed-only rather than mere caution
- (decision) Geometry path is wire -> BRepOffsetAPI_MakeOffset(wire, GeomAbs_Arc) -> Perform(d) -> walk result edges with BRepAdaptor_Curve, mapping GeomAbs_Line to addLine and GeomAbs_Circle to addArc/addCircle; deliberately NOT SvgImport's sample-to-polyline, which throws away editability because it only needs a render outline
- (decision) The input wire is built from the selected entity ids directly rather than reusing Sketch::buildWires(), because buildWires returns bare OCCT wires with no link back to sketch ids so there is no way to tell which wire the user selected
- (decision) commitOffset adds ordinary points/lines/arcs/circles to the sketch, so undo, autosave and .materializr serialization ride the existing sketch path unchanged -- no new modeling op, no serializeParams/deserializeParams, and therefore no new ParamParse untrusted-input surface
- (decision) Offset is non-associative: editing the source loop afterwards does not move the offset copy, matching Mirror's one-shot behaviour
- (capability) CAP-1 drag a closed selected loop to offset it, side and distance from the cursor, with a live ghost preview
- (capability) CAP-2 commit an exact offset distance by typing it into the existing typed-value popup
- (capability) CAP-3 offset output is editable sketch entities (lines, arcs, circles), so it can be selected, dimensioned and constrained like drawn geometry
- (capability) CAP-4 a selection that is not exactly one closed loop is refused with a specific message rather than silently guessing
- (capability) CAP-5 an offset that collapses or degenerates commits nothing and says so, rather than appearing to succeed
- (capability) CAP-6 offset output survives undo/redo and a save/reload round-trip

- (constraint) The stale-source guard added in round 1 was wrong: Sketch::geometryHash() is FNV-1a over every point/line/circle/arc (Sketch.cpp:1562+), so committing offset output changes it, and because the machine re-arms after commit the next preview would detect its own output as a stale-source edit and self-cancel. The guard must hash only the CAPTURED SOURCE entities, not the whole sketch
- (decision) Typed entry uses a bespoke Mirror-style panel in Application_Dialogs.cpp, NOT the ##SketchDimInput popup. Reason: applyDimension opens with if (!m_sketch || !m_isPlacing || value <= 0) return false and its mode switch ends default: return false (SketchTool.cpp:398-407,554), and Offset never sets m_isPlacing -- so adding a label case would have produced a field that silently does nothing. - (decision) Sub-tolerance magnitude is REFUSED, not clamped, resolving a direct contradiction between state-machine.md (clamp to floor) and SPEC.md (refuse below tolerance). No preview is drawn below tolerance either
- (constraint) Named tolerances, all in sketch millimetres: kMinOffsetDistance 1e-3 (below this, refuse before OCCT); kEndpointWeldTol 1e-6 (result-to-result endpoint coincidence, NOT the 0.3*snapScale UI radius); kZeroLengthEdgeTol 1e-6; kIntersectionTol 1e-6. Fixed values, not scaled by zoom or touch mode, because they describe geometry rather than pointer precision
- (decision) Canonical winding: the assembled source wire is reoriented to positive signed area (CCW) before Perform, and a lone circle is emitted CCW explicitly since it has no endpoint walk to derive orientation from. After canonicalisation a POSITIVE Perform argument is outward. Cursor sign maps to that convention; ties (cursor equidistant, e.g. at a circle centre) resolve outward
- (constraint) Commit is a two-phase transaction: convert the entire OCCT result into an in-memory plan of intended entities first, and only mutate Sketch once conversion has fully succeeded. recordSketchMutation records before/after for undo but does NOT roll back a partial failure or an exception (Sketch mutators append directly, Sketch.cpp:96/199/210), so all-or-nothing does not follow from the wrapper alone
- (constraint) Loop validation predicates specified rather than left outcome-based: build an adjacency graph over captured entity endpoints welded at kEndpointWeldTol; require every vertex degree exactly 2, exactly one connected component, no zero-length edges, no duplicate entity ids, and no non-endpoint intersection between any entity pair (line-line, line-arc, arc-arc) at kIntersectionTol. Tangential contact at a shared endpoint is permitted; tangential contact anywhere else is refused

- (event) Codex review round 3: 8 findings, VERDICT REVISE
- (constraint) beginOffset must RESTORE the captured selection after calling setMode. setMode runs clearElementSelection() for any mode other than Select (SketchTool.cpp:37), so capture-then-setMode leaves the source unselected, contradicting the round-1 decision that the source stays selected. Re-arm after commit must preserve it too
- (constraint) Adjacency for loop validation is built on SHARED POINT IDS, not positions: SketchLine already references startPointId/endPointId, so shared-vertex detection is exact, scale-free and correct by construction. Positional welding survives only as a fallback for coincident-but-distinct points
- (constraint) The 1e-6 mm tolerances were unusable: SketchPoint::pos is glm::vec2 (single precision, Sketch.h:19) and measured float ULP is 7.6e-6 mm at 100 mm, 6.1e-5 at 1000 mm and 9.8e-4 at 10000 mm -- so 1e-6 predicates fall below representable resolution over most of the working range and change meaning as a sketch translates away from the origin. Positional predicates are now scale-aware (absolute floor OR a ULP multiple at the coordinate magnitude, whichever is larger) and evaluated in double precision
- (decision) CAP-2's Hausdorff bound REMOVED rather than specified. It named no metric, bound or fixture, and the analytic per-entity invariants (parallel line at distance d; derived arc at source +/- d; join fillet at exactly |d|) already pin every generated entity. Specifying it properly would have been ceremony around a redundant check
- (decision) Offset direction initialises to OUTWARD at Arm, so a user who types a value and presses Enter before moving the mouse gets a deterministic result instead of one depending on stale cursor state
- (decision) Duplicate-edge validation redefined as two DISTINCT entity ids holding geometrically coincident geometry. Duplicate ids cannot actually reach the validator since selections are std::set<int> (SketchTool.h:90); that check is retained only as cheap defensive validation
- (constraint) Integration points additions: renderOffsetToolPanel() needs a declaration in Application.h beside renderMirrorToolPanel() (Application.h:128) and a per-frame invocation beside it in Application.cpp (:7569). Neither file was listed before

- (constraint) Loop adjacency is TWO-STAGE: exact shared-point-id match first, then a weldTol union of still-distinct endpoint ids in double precision. Stage 2 is required, not garnish: an imported loop can be geometrically closed while every junction holds two distinct coincident ids, and under id-equality alone it presents as degree-1 vertices and is wrongly rejected as open

Hashing only ids, endpoint positions and radii would miss circle and arc CENTRES -- SketchCircle is {centerPointId, radius} and SketchArc is {centerPointId, startPointId, endPointId, radius} (Sketch.h:43-58) -- so dragging a circle centre while Offset was live would go undetected
